# Вакансии аналитиков с hh.ru

Собирает вакансии трёх направлений — системный аналитик, аналитик данных (BI), продуктовый аналитик —
с веб-страниц hh.ru и складывает в CSV: ссылка, работодатель, зарплата, опыт, формат работы, ключевые навыки.
Цель — понять, какие навыки требует рынок, и взять ключевые слова для резюме.

Анонимный API hh закрыт, поэтому данные берутся из JSON, встроенного в страницы поиска и вакансий
(тот же способ, что в проекте SVO VET JOB FIND). Правила hh автоматический сбор не разрешают: скрипт
работает медленно (пауза 1,5–3 с между запросами), только для личного анализа, и при капче
останавливается, а не обходит её.

## Запуск

```bash
python collect.py
```

Около 1300 вакансий по Москве за 30 дней — примерно час. Прерванный запуск продолжается с места
остановки: разобранные карточки лежат в `data/cache/`. Чтобы собрать заново, удалите эту папку.

Настройки — в начале `collect.py`: `AREA` (1 — Москва, 113 — вся Россия), `PERIOD_DAYS` (1, 3, 7 или 30),
`DIRECTIONS` (коды профессиональных ролей hh: 148 — системный, 156 — BI и данные, 164 — продукт).

## Что получается в `data/`

| Файл | Строка | Колонки |
| :--- | :--- | :--- |
| `vacancies.csv` | вакансия | id, направления, название, работодатель, город, опыт, формат работы, зарплата, дата создания, дата публикации, дней с создания, отклики, отклики в день, ссылка, ключевые навыки через «;» |
| `skills.csv` | пара «вакансия — навык» | id, направления, навык |
| `skills_top.csv` | навык в направлении | направление, навык, число вакансий, доля от всех вакансий направления (`share`), доля от вакансий с заполненными навыками (`share_with_skills`), % |

Направление берётся из профессиональной роли, которую указал работодатель. Вакансия с двумя ролями
попадает в оба направления и в `skills_top.csv` считается в каждом.

Дата создания и отклики берутся из выдачи поиска при каждом запуске, поэтому всегда свежие.
Дата создания — первое размещение вакансии; дата публикации обновляется, когда работодатель поднимает
вакансию, поэтому срок считается от создания. Отклики в день = отклики / дней с создания (по часам,
не меньше одного дня). У вакансий младше недели эта метрика шумная и обычно завышена: в первые дни
вакансия стоит наверху выдачи.

Ключевые навыки — только поле «Ключевые навыки». Требования из текста вакансии сюда не входят,
а у части вакансий это поле пустое — сколько таких, `collect.py` печатает в конце.

Если hh поменяет вёрстку, скрипт сообщит «на странице нет данных» — нужно заново найти, где лежат поля.

CSV — UTF-8 с BOM, разделитель `;`, открываются в Excel.

## SQL по выгрузке

DuckDB читает CSV из `data/` напрямую, сервер базы не нужен. Таблицы описаны в `sql/views.sql`:

| Таблица | Строка | Что добавлено к CSV |
| :--- | :--- | :--- |
| `vacancies` | вакансия | `has_skills` — заполнены ли навыки; `salary_mid` — середина вилки в рублях |
| `vacancy_directions` | вакансия × направление | `direction` — одно направление; для подсчётов по направлениям |
| `skills` | вакансия × направление × навык | — |
| `skills_top` | навык в направлении | то, что посчитал `collect.py`, для сверки |

Запуск файла с запросами (результат в терминале и полностью в `sql/out/<файл>_<номер>.csv`):

```bash
python sql/run.py sql/checks/01_overview.sql
```

В VS Code — Ctrl+Shift+B на открытом `.sql`-файле. Свои запросы кладите в `sql/checks/`, по одному файлу на вопрос.
